# 02 · 语音转写

## 语音存在哪

微信 4.x 的语音**不在文件系统里**，而是以 SILK blob 存在
`db_storage\message\media_*.db` 的 `VoiceInfo` 表：

```
VoiceInfo(chat_name_id, create_time, local_id, svr_id, voice_data, data_index)
```

`voice_data` 的开头是 `02 23 21 53 49 4c 4b 5f`（`\x02#!SILK_`），即标准 SILK 文件。

命名约定（导出工具与转写脚本都用它）：
```
<create_time>_<local_id>.silk
```

## 为什么不直接转写 SILK

**ffmpeg 解不了 SILK**（属非自由编解码）。两条路：

1. 用导出工具自带的 HTTP 接口 `/api/voice?path=...` 做 SILK→WAV（最省事）
2. 自己编 SILK 解码库（麻烦）

本仓库用第 1 条：`wx_voice_dump.py` 把 blob 写成 `.silk` 放到备份目录的
`media/voice/` 下，再让转写脚本通过工具接口取 WAV。

## 转写

用 [faster-whisper](https://github.com/SYSTRAN/faster-whisper)（CTranslate2 后端）：

- 模型：`small` 在中文语音上够用；追求质量可换 `medium` / `large-v3`
- GPU：CUDA 下 `float16`，实测约 **16 倍实时**（`beam_size=1`）
- 分片：`--shard i --shards N` 多进程并行（每进程独立加载模型）
- 缓存：按 `文件名+模型名` 哈希缓存文本，重跑几乎零成本

## 产出与回填

- `_voice_text/<name>.txt`：每条语音的文字
- `voice_transcripts.jsonl`：合并后的全量结果
- 重新跑一次 `wx_export_db.py`，会按 `(create_time, local_id)` 把文字写进
  CSV 的「语音转写」列

## 注意事项

- ASR **一定有错字**：专业术语、方言、中英夹杂、人名。逐字引用时保留原样，
  不要"顺手改正"，否则引用就不可追溯了。
- 有些语音的 blob 不在本地（未下载/已过期），覆盖率通常在 80–90%。
- 转写完成后如果不需要回听，**删掉 `.silk` 和临时 WAV** 能省大量空间
  （实测上千条语音约 800+ MB）。
