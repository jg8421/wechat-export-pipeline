# 01 · 解密与导出

## 微信 PC 版（4.x）的数据结构

```
<微信数据目录>\                      例如 %USERPROFILE%\Documents\xwechat_files
├─ all_users\sqlite\
├─ <wxid>_<suffix>\
│   ├─ config\                       登录配置（含 Config.Cipher）
│   ├─ db_storage\                   ← 关键
│   │   ├─ contact\contact.db        联系人（username / remark / nick_name）
│   │   ├─ message\message_0..N.db   消息，按会话分表
│   │   ├─ message\media_0..N.db     语音等媒体索引（VoiceInfo 表）
│   │   ├─ hardlink\hardlink.db      图片/文件/视频的 md5 → 文件名映射
│   │   ├─ session\session.db        会话列表
│   │   └─ ...
│   └─ msg\attach\<hash>\<YYYY-MM>\  图片/文件/语音的实际文件
```

## 密钥从哪来

微信 4.1.10+ 的密钥可以在**不重启微信、不需要管理员权限**的情况下，从进程内存中
只读提取（第三方工具普遍这么做）。工具会把每个库的密钥缓存到自己的配置文件里，
之后即使微信没开也能解密。

> 密钥文件 = 全部聊天记录的钥匙。**绝不要提交到任何仓库**（本仓库 .gitignore 已屏蔽）。

## 第三方工具

社区里有多款开源导出工具，能力相近。选择标准：

1. 支持你当前的微信大版本（4.x 改过密钥派生方式）
2. 能在微信运行状态下提取密钥
3. 有可校验的 release（比对 SHA-256）
4. 仍在维护

工具通常提供三种用法：Web UI、CLI、以及本地 HTTP API。**本仓库只用它做「解密 + 媒体迁移」这一步**，
之后的解析全部自己写（见下）。

## 为什么不用工具的 HTTP API 拉消息

工具的 Web API 返回结构化 JSON，很省事，但**在大会话上极慢**：实测某些几万条消息的群，
每 200 条要 60–90 秒。全部会话拉完要几小时甚至更久。

改成**直读解密后的 SQLite**之后，同样的数据量只要**几十秒**（实测约 40 万条 59 秒）。

## message_content 的存储格式

- 表名：`Msg_<md5(会话username)>`，即每个会话一张表
- 关键列：`local_id, create_time, real_sender_id, local_type, message_content`
- `message_content` 可能是：
  - 明文 UTF-8 字符串（Python 读出来直接是 `str`）
  - **zstd 压缩的 BLOB**（magic `28 b5 2f fd`）→ 必须解压

⚠️ zstd 帧可能**不写 content size**，此时 `dctx.decompress()` 会抛异常，
要用 `dctx.decompressobj().decompress()` 兜底。

## local_type 的编码

微信 4.x 把「子类型」和「主类型」打包进一个整数：

```
local_type = (subtype << 32) | base_type
base_type  = local_type & 0xFFFFFFFF
```

例：`244813135921 = (57 << 32) | 49` → 主类型 49（应用消息）+ 子类型 57（引用）。

常见主类型：1 文本、3 图片、34 语音、43/62 视频、47 表情、42 名片、48 位置、
49 应用消息、50 语音通话、10000 系统消息。

## 发送者归属

| 场景 | 判定方法 |
|---|---|
| 一对一 | `real_sender_id → Name2Id → username`；等于会话 username 就是对方，否则是自己 |
| 群聊 | `message_content` 以 `<sender_wxid>:\n` 开头，前缀即发送者 |
| 自己 | 需要知道**自己的 wxid**（数据目录名里就有：`xwechat_files\<wxid>_abcd\`） |

## 输出

每会话一个目录，含 `chat.csv`（固定列）、`meta.json`（条数、时间范围、类型）。
列约定见 README。
