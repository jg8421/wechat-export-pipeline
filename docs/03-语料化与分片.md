# 03 · 语料化与分片

## 按人归集（wx_by_person.py）

同一个人可能在多处出现：

- **一对一聊天**：整个会话都属于他
- **群聊**：只取他的发言，并带上前后若干条上下文（默认 ±3 条）

产出（每人一个目录）：

```
<人名>_1v1.csv     一对一全部消息
<人名>_groups.csv  群聊发言 + 上下文（带「会话」列）
<人名>_all.txt     可读文本（含语音转写）
<人名>_*.html      可搜索浏览页（可选）
```

## 过滤策略（wx_person_corpus.py）

原始记录噪音极大，直接喂给模型会浪费预算。做法是**上下文保留式过滤**：

1. 丢弃纯噪音类型：表情、系统消息
2. 丢弃机器人/公众号：文件名传输助手、邮箱提醒、外卖红包助手等（正则可配）
3. 丢弃明显的广告/导流（扫码、加群、开户、返佣…）
4. **保留有实质内容的发言**：对方 ≥ N 字（默认 12）、自己 ≥ M 字（默认 20）
5. 对被保留的消息，**前后各取 K 条作为上下文**（默认 ±3）
6. 跨天处插入「----- 日期跳转 -----」标记
7. 按 4 万字切分成片

## 为什么是「上下文保留」

单独一句「按这个口径改」没有意义；带上前后几句才知道在改什么。
上一版用「对方 ≥16 字、自己 ≥30 字、±4 条上下文」，压缩到原量的 ~1/4，信息几乎不丢。

## 分片尺寸

- 每片 3–4 万字（≈ 20–35k token），一个 subagent 一次能读完
- 太长会截断，太短则跨片重复上下文、且 subagent 数量爆炸

## 质量控制

- `wx_report.py` 输出全量总览：会话数、条数、字数、类型分布、语音覆盖率
- 每人的 `_stats.json` 记录 kept / chars / chunks，便于判断是否值得提炼
